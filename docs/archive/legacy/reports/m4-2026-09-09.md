（877,544 / 954,294），输出 token 比为 **1.10×**（22,336 / 20,218），

## 失败明细与产品反馈

第二轮的 Shell `jsonl_recovery`、`repair_moon`、`background_job` 均被
`502 Bad Gateway` 中断，各记录了六次失败的 HTTP 请求。其中 JSONL 已输出
正确文件，repair 只开始了一次工具调用，background 尚未进入工具执行。
这些是服务端可用性问题，原记录与失败门禁全部保留。

MBTX 共调用 58 次，记录 14 次 `script_exit`，零次 `runner_error`。
保留诊断主要为模型遗漏 async 导入、Map 遍历语法错误、误加 `mut`、调用不存在
的 API 等，最终均恢复完成。通用参考已经解决首次读文档时的语法引导问题，
但脚本生成仍有纠错开销；下一阶段值得改进可执行模板和 API 发现，再另起
固定配置的独立评测。

两次 MBTX 后台任务都真实启动了 background run，并使用 `job_output` 轮询。
六类任务都完成了两次：JSON/JSONL、特殊路径与 UTF-8、参数字面量、MoonBit
函数修复、后台执行。实际 MBTX 调用没有 shell 回退。

本实验使用 Direct tools，未验证 JavaScript Code Mode、Codex 桌面定时自动化、
本地模型部署或多平台性能。测试是非对抗性任务评测，不是安全渗透测试。
两组都使用 approval `never`，人工干预为零不代表测得了交互产品中干预次数的降低。

## 工程修复与验证

本轮真实执行推动了三项已交付的修复：

1. 正确文件曾被 `Option[String]` 的数组包装误判。现显式编码字符串或 null，
   CLI 拒绝其他形状；回归覆盖正确内容、缺失文件和旧数组包装。
2. MoonBit 编译输出可能包含多条警告 JSON 和一条产物 JSON。运行器现逐行解析，
   警告保留到 stderr，合法脚本继续执行；有带警告脚本的实际运行回归。
3. 增加绝对序号续跑，避免触及单次观察量阈值后重复已完成任务。原任务顺序、
   smoke 成对执行要求、无效范围校验及 CLI 协议都有回归检查。

实现提交 `e5b7a66` 的 [普通 CI](https://github.com/ZSeanYves/Codex-MBTX/actions/runs/34254898543)、
[M4 离线 CI](https://github.com/ZSeanYves/Codex-MBTX/actions/runs/34254898440)
和 [M3 集成与构建](https://github.com/ZSeanYves/Codex-MBTX/actions/runs/34254898451)
均已通过，包括真实运行器集成、受影响的 Codex 回归、Clippy、格式、schema、
可复现补丁和二进制构建。评测所用二进制的
[M3 工作流](https://github.com/ZSeanYves/Codex-MBTX/actions/runs/34222760643)也已通过。

本地与独立干净工作树均通过 Wasm 52/52、Native 52/52；干净工作树另通过
无警告检查、三个可执行样例、证据与计划 CLI 回归、接口和格式检查。
两段每行的保留输出都已按原 suite 重验，判分一致。

两个 live workflow 均未通过：第一段在预算保护阈值处停止，第二段因 502
触发 `evaluation evidence is incomplete`。工程 CI 通过不能替代这个事实。
若验收要求一次完整 live 全绿，仍需稳定的 Responses 通道，并在运行前确定
足以覆盖 24 项的预算或明确分段计划。当前结论支持保持 MBTX 为可选后端。
